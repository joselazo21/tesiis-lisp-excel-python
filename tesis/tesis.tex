\chapter*{Opini\'on del Tutor}
\addcontentsline{toc}{chapter}{Opini\'on del Tutor}
\thispagestyle{plain}

La gesti\'on de la informaci\'on en entornos acad\'emicos genera, de forma
recurrente, documentos de planificaci\'on tabular: horarios de docencia,
calendarios de defensas, distribuciones de aulas.  Cuando se quiere automatizar
la creaci\'on de esos documentos se repite invariablemente el mismo patr\'on:
c\'odigo imperativo que mezcla la l\'ogica del problema con los detalles de
la \textit{API} de la biblioteca de salida elegida, ya sea una hoja de c\'alculo,
una base de datos o un servicio web.  El resultado es c\'odigo fr\'agil,
dif\'{\i}cil de mantener y poco reutilizable.

El trabajo que se presenta en este documento aborda precisamente ese problema.
Jose Morales Lazo dise\~n\'o e implement\'o un lenguaje de dominio espec\'{\i}fico
(DSL) interno en Common Lisp que permite declarar tablas relacionadas, columnas
calculadas, reglas de visualizaci\'on condicional y relaciones entre estructuras,
sin hacer referencia a ning\'un detalle concreto del sistema de salida.
El AST resultante es independiente del backend; como demostraci\'on de
viabilidad, se implement\'o un backend que genera el programa Python que
construye el archivo \xlsx{} con todas las f\'ormulas y reglas de formato
condicional incrustadas.

El diplomante demostr\'o durante el trabajo una notable capacidad para
identificar la abstracci\'on correcta, dise\~narla y construirla con rigor.
Los tres casos de uso reales validados ---horario de defensas de tesis,
horario docente de la facultad y horario de programaci\'on televisiva---
muestran que el lenguaje es suficientemente expresivo para cubrir problemas
de complejidad creciente.

Estoy muy satisfecho con los resultados obtenidos y considero que el trabajo
re\'une los m\'eritos suficientes para optar al t\'{\i}tulo de Licenciado en
Ciencia de la Computaci\'on.

\chapter*{Resumen}
\addcontentsline{toc}{chapter}{Resumen}
\thispagestyle{plain}

Describir visualizaciones de estructuras tabulares ---horarios, calendarios,
distribuciones--- exige, en la pr\'actica, c\'odigo imperativo que entremezcla
la l\'ogica del problema ---qui\'en tiene conflicto de horario, cu\'antas
defensas acumula un profesor--- con los detalles mec\'anicos del sistema de
salida elegido: \'{\i}ndices de columna, rangos absolutos, cadenas de f\'ormula,
llamadas a la API del generador.  Esta mezcla eleva el costo de desarrollo y
dificulta la reutilizaci\'on ante cambios en los datos o en el backend de destino.

El objetivo de este trabajo es separar ambas capas mediante un lenguaje de
dominio espec\'{\i}fico (DSL) interno en Common~Lisp.  El programador declara
\emph{qu\'e} debe contener la estructura ---tablas relacionadas, columnas
calculadas, cuantificadores existenciales, reglas de coloreado condicional,
totales con posicionamiento relativo--- y un compilador basado en el Sistema de
Objetos de Common Lisp (CLOS) traduce esa declaraci\'on a trav\'es de un \'arbol
de sintaxis abstracta independiente del backend.  Como demostraci\'on, se
implementa un backend que genera programas Python los cuales construyen archivos
\xlsx{} mediante la biblioteca openpyxl, con reglas de formato condicional
persistentes incrustadas como \texttt{FormulaRule}.

La validaci\'on sobre tres casos reales de la Facultad de Matem\'atica y
Computaci\'on de la Universidad de La Habana confirma que el lenguaje captura
los patrones recurrentes de la planificaci\'on tabular con una cantidad
de c\'odigo significativamente menor que la alternativa imperativa, e
independientemente de los detalles de cualquier API de salida.

\medskip\noindent
\textbf{Palabras clave:} Lenguaje de dominio espec\'{\i}fico; Estructuras
tabulares; Generaci\'on de c\'odigo; Common Lisp; CLOS; Macros;
Formato condicional; openpyxl.

%  ABSTRACT

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
\thispagestyle{plain}

Describing visualizations of tabular structures---schedules, calendars,
distributions---requires, in practice, imperative code that interleaves
domain logic---who has a scheduling conflict, how many thesis defenses a
professor is involved in---with the mechanical details of the chosen output
system: column indices, absolute ranges, formula strings, and output API calls.
This interleaving raises development costs and hampers reuse when data or
the target backend changes.

The objective of this work is to separate these two layers through an
internal domain-specific language (DSL) built in Common~Lisp.  The
programmer declares \emph{what} the structure should contain---related
tables, computed columns, existential quantifiers, conditional coloring
rules, relative totals---and a compiler based on the Common Lisp Object
System (CLOS) translates that declaration through a backend-independent
abstract syntax tree.  As a demonstration, a backend is implemented that
generates Python programs which build \xlsx{} files via the openpyxl
library, with persistent conditional formatting rules embedded as
\texttt{FormulaRule} objects.

Validation on three real use cases from the Faculty of Mathematics and
Computer Science of the University of Havana confirms that the language
captures the recurring patterns of tabular planning with significantly
less code than the imperative alternative, independent of any specific
output API.

\medskip\noindent
\textbf{Keywords:} Domain-specific language; Tabular structures;
Code generation; Common Lisp; CLOS; Macros;
Conditional formatting; openpyxl.
